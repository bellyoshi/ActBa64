# コーディング規約

ActBa64 のソース（主に `.abp` / `.sbp` / `.wbp`）向け。言語仕様は [language.md](./language.md)、ビルドは [build.md](./build.md)。

## 1. ファイル行数

| 規則 | 内容 |
|---|---|
| **目標** | **できれば 400 行以下** |
| **上限** | **最大 1000 行**（これを超えない） |
| 対象 | `src/actba64`・`src/Include`・`src/projecteditor` の `.abp` / `.sbp` / `.wbp`。テスト・サンプルも同じ |
| 超過時 | 機能単位でファイルを増やす。単一の巨大ファイルに足し続けない |

新規ファイルは最初から 400 行以下を目指す。既存が 400 を超えていても、触る範囲で分割を進める。

### 分割のしかた

- **関数 / Sub の境界で切る**。`End Function` / `End Sub` の途中や、`If` ブロックの途中で切らない
- 各分割ファイルは `Function` / `Sub` / `Type` / `Const` / `Dim` などトップレベルで始め、`End Function` / `End Sub`（または `End Type`）で終わる
- 共有の `Type` / `Dim Shared` / モジュール `Dim` は、結合順で先に来る先頭ファイルに置く
- コンパイラ本体は `actba64.pj` の `#SOURCE`（および `actba64.idx` の `#include`）に **結合順どおり** 追加する

現行の Parser / AstLower / Preproc 分割一覧は [build.md §コンパイラソースの分割](./build.md#コンパイラソースの分割)。

### 結合の前提

`#SOURCE` / `#include` で連結されると **1 コンパイル単位** になる。分割は編集・レビュー用の物理ファイル分けであり、名前空間は分かれていない。

## 2. 関数の長さ

| 規則 | 内容 |
|---|---|
| **上限** | **1 つの `Function` / `Sub` は 10 行以内**（`Function`/`Sub` 行から対応する `End Function`/`End Sub` まで） |
| 超過時 | ヘルパに切り出す。巨大な `If` / `Select` チェーンは条件種別ごとの手続きへ分ける |

新規・改修コードはこの上限を守る。既存の長い手続きは触るときに段階的に分割する（無関係な一括リファクタはしない）。

## 3. スタイル（既存コードに合わせる）

- 既存ファイルのインデント・命名・コメント密度を維持する（無関係な整形だけしない）
- 手続き名は役割が分かる接頭辞（例: `Parse*` / `Low*` / `Pp*`）
- Include 側の公開 API は薄いラッパ＋実体、という既存パターンに従う（例: `Print` → `StrD$`、ファイル I/O → `BaFile*`）
- **stage0（AB 4.20）予約語に注意**: `Line` は図形命令のため、行番号用ローカルは `srcLine` など別名にする（`line = …` は「パラメータ指定が間違っています」になる）
- **ソース 1 行は最大 1024 バイト**（`PP_LINE_MAX`）。長い条件は `_` や括弧内改行で分割する（詳細は [language.md §7.1](./language.md#71-行長上限)）

## 4. 変更時のチェック

1. 追加・編集後、該当ファイルが **できれば 400 行以下・必ず 1000 行以下**、変更した手続きが **10 行以内**か確認する
2. 分割したら `actba64.pj` / `actba64.idx`（または当該 `.pj`）を更新する
3. コンパイラ変更なら `src/actba64` で `.\build.ps1 -Stage1Only` と回帰（必要なら stage2 比較）
